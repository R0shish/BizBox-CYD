# BizBox-CYD — notes for Claude

Business-hub / payment soundbox firmware for the ESP32 Cheap Yellow Display (ESP32-2432S028). Public, open-source repo: keep secrets, personal details and private URLs out of commits (previews use sample data only). Arduino sketch, single translation unit: `esp.ino` includes the libraries, then `textutil.h` `hw.h` `model.h` `ui.h` `speaker.h` `imap.h` `net.h` `storage.h` `connect.h` `nettask.h` `app.h` `input.h` `wifi.h` `presets.h` `web.h` in that order (each header only uses what's above it). `qr_encode.c` is the one C file.

## Hardware (CYD)
- Display ILI9341 320×240 via TFT_eSPI, rotation 1. Backlight PWM on GPIO21.
- Touch XPT2046 is bit-banged in `CYDTouch` (MOSI 32, MISO 39, CLK 25, CS 33, IRQ 36). GPIO25 is the touch clock: never drive it from audio code.
- Speaker amp is on GPIO26 = ESP32 DAC channel 2. `speaker.h` writes samples into the DAC register from a 22.05 kHz hardware timer. Do NOT go back to `AudioOutputI2S(…, INTERNAL_DAC)`: ESP8266Audio 2.x ignores that mode and puts the I2S clock on GPIO26 (distorted voice), and `AudioOutputInternalDAC` outputs mono on GPIO25.
- BOOT button (GPIO0) held 3.5 s = factory reset.

## Two tasks
- The Arduino loop task owns the TFT, audio, orders, stats and `cfg`. The network task (`nettask.h`, core 0) does all TLS/IMAP/HTTP: payment polling, Connect webhooks and pull. Never draw, speak or touch orders from it.
- Network task -> loop: `NetEvent`s through `netQueue` (fixed-size structs, no `String`s). Loop -> network task: flags (`netPollNow`, `cxPullNow`, `cxCursorReset`) and the Connect webhook queue (guarded by `cxLock`).
- The network task copies the settings it needs under `cfgLock` when `cfgVersion` changes. Anything that changes those fields must take `CfgLock` and bump `cfgVersion` (see `handleSave`).
- Status text shown on the dashboard goes through `StatusText` (spinlock), not plain `String`s.
- Announcements are queued (`queueAnnouncement`); never call `announce()` from an HTTP handler.

## Must stay true
- Compiles on ESP32 Arduino core **2.x (C++11)** and **3.x**. No C++14/17 features (no `inline` variables, no generic lambdas, no `std::optional`). Core-specific APIs go behind `ESP_ARDUINO_VERSION_MAJOR >= 3` (ledc, hw timers).
- TFT_eSPI 2.5+ with `SMOOTH_FONT`. Always pass an explicit background colour to smooth shapes/text (`fillSmoothRoundRect(..., bg)`, `setTextColor(fg, bg)`): the CYD can't reliably read pixels back.
- Flash is tight: core 2.x fits the default 1.25 MB app partition, core 3.x needs Huge APP. CI reports both on every push. `fonts.h` is ~80 KB; think before adding fonts.
- NVS key names (namespace `cydbiz`) are an upgrade contract: never rename one. List in `storage.h` and docs/CONNECT.md.
- Secrets (Gmail app password, PIN, Connect header/secret) are never written into a page; blank means "keep".
- `/api/*` needs the Bearer token (`apiAuthed()`), dashboard forms need the `csrf` nonce (`FORM_OPEN`).
- Amounts are paisa (`uint32_t`) everywhere except today's totals (whole rupees plus `salesPaisa` carry) and the hourly bars.
- Every network read has a deadline. Core 2's `WiFiClientSecure::setTimeout()` takes seconds; don't use it or `readStringUntil` on sockets.
- The Arduino IDE can silently overwrite files you edit if it has them open and the user saves. If changes "disappear", that's usually why.

## UI system (`ui.h`)
- Palette: `UI_BG` #0D1F33, `UI_SURF` #153250 (PrintLab navy), `UI_LINE`, `UI_INK` #F0F0F0, `UI_MUTED`, `UI_DIM`, accents `UI_CYAN` / `UI_GREEN` / `UI_YELLOW` / `UI_RED`, plus the 7 PrintLab filament colours (`ui_strip`).
- Fonts (`FT_LABEL` mono 10px tracked, `FT_MONO` 12, `FT_BODY` grotesk 15, `FT_HEAD` 24, `FT_NUM` 40 digits, `FT_HERO` 58 digits). Generated by `tools/fonts/gen_fonts.py`; NUM/HERO only contain `0-9,.:-+`.
- Draw text with `ui_text(s, x, baselineY, font, fg, bg, AL_L|AL_C|AL_R)`: y is the **baseline**. `ui_w`, `ui_fit` (ellipsis, UTF-8 safe), `ui_wrap` for measuring/fitting.
- Fonts are parsed once and cached by swapping TFT_eSPI's public `gFont`/`g*` arrays (`ui_font`). Never call `tft.loadFont`/`unloadFont` anywhere else.
- Redraws: `ui_drawScreen()` (full) only after the payment takeover, at boot and after a dashboard Save. Screen switches use `redrawContent()` (content + nav). Value changes use the partial helpers (`ui_settingValue`, `ui_orderRow`, `ui_ordersChip`, `ui_statsSwitch`). A partial redraw must leave exactly the pixels a full one would; `tools/preview.sh` checks this.
- Spaces are swapped to U+00A0 inside `ui_text`/`ui_w` because TFT_eSPI guesses the width of 0x20; the fonts carry a real NBSP glyph.
- Layout: status bar 0–21 (hairline at 21), content 22–207, nav 208–239 (5 tabs × 64 px). Touch hit areas are constants in `ui.h` shared with `handleTap` (`input.h`).
- Voice/tone: headlines are short and end with a full stop ("Scan to pay.", "Today."); labels are uppercase mono with "01 / NAME" numbering.

## Verifying changes (no hardware here)
- `tools/check.sh` compiles the full sketch against stubs for core 2 and 3 with `-Wall -Wextra` and runs the unit tests: audio, `logic_test.cpp` (textutil: amounts, MIME, words, IMAP parsing, templates) and `firmware_test.cpp` (the real sketch: orders/NVS round-trip, token, sales, Connect queue/retries/signatures/pull mapping). It needs the real ArduinoJson 7 (`ARDUINOJSON_SRC` or the Arduino libraries folder). Stubs live in `tools/check/stubs` and `tools/sim/stubs`; extend them when you use a new library API (and check the real library's signature first). The Preferences stub is a real in-memory store and, like the real class, ignores reads/writes outside `begin()`/`end()`. The HTTPClient stub is scriptable via `HTTPClient::fake()`.
- `tools/preview.sh` renders every screen to `previews/` using a TFT_eSPI stand-in that parses the same VLW fonts, stores them in the same public members, and follows TFT_eSPI's datum/textWidth/alphaBlend rules. It also checks partial redraws against full ones. Look at the PNGs after any UI change. `--web` also renders the dashboard and rebuilds `previews/dashboard-previews.png` (`CHROMIUM=` to reuse a browser).
- CI (`.github/workflows/build.yml`) builds with arduino-cli for core 2.0.17 and 3.x (Huge APP partition), reports size against the default partition, and runs `tools/check.sh`. Push and read the job results: it's the only real compiler available.
- QR codes in the simulator come from `tools/sim/stubs/qr_table.h`; add strings with `tools/sim/gen_qr.py` if a preview needs a new one.

## Direction
- Goal: deep integration with the maintainer's own business dashboard (PrintLab Nepal), built as a preset on top of the generic Connect layer (`connect.h`, docs/CONNECT.md), so any management system can plug in: payments → system, orders → screen, status changes → system, system → speak. The device sits behind NAT, so inbound data is pulled by the device, and outbound goes as signed webhooks. Vendor presets go in the marked block in `presets.h`. Money-moving commands (`announce`) only run from HMAC-signed pull replies.
