# BizBox-CYD — notes for Claude

Business-hub / payment soundbox firmware for the ESP32 Cheap Yellow Display (ESP32-2432S028). Public, open-source repo: keep secrets, personal details and private URLs out of commits. Arduino sketch, single translation unit: `esp.ino` includes `model.h`, `ui.h`, `speaker.h`, `web.h` in that order.

## Hardware (CYD)
- Display ILI9341 320×240 via TFT_eSPI, rotation 1. Backlight PWM on GPIO21.
- Touch XPT2046 is bit-banged in `CYDTouch` (MOSI 32, MISO 39, CLK 25, CS 33, IRQ 36). GPIO25 is the touch clock: never drive it from audio code.
- Speaker amp is on GPIO26 = ESP32 DAC channel 2. `speaker.h` writes samples into the DAC register from a 22.05 kHz hardware timer. Do NOT go back to `AudioOutputI2S(…, INTERNAL_DAC)`: ESP8266Audio 2.x ignores that mode and puts the I2S clock on GPIO26 (distorted voice), and `AudioOutputInternalDAC` outputs mono on GPIO25.
- BOOT button (GPIO0) held 3.5 s = factory reset.

## Must stay true
- Compiles on ESP32 Arduino core **2.x (C++11)** and **3.x**. No C++14/17 features (no `inline` variables, no generic lambdas, no `std::optional`). Core-specific APIs go behind `ESP_ARDUINO_VERSION_MAJOR >= 3` (ledc, hw timers).
- TFT_eSPI 2.5+ with `SMOOTH_FONT`. Always pass an explicit background colour to smooth shapes/text (`fillSmoothRoundRect(..., bg)`, `setTextColor(fg, bg)`): the CYD can't reliably read pixels back.
- Flash is tight (default 1.2 MB app partition). `fonts.h` is ~80 KB; think before adding fonts.
- The Arduino IDE can silently overwrite files you edit if it has them open and the user saves. If changes "disappear", that's usually why.

## UI system (`ui.h`)
- Palette: `UI_BG` #0D1F33, `UI_SURF` #153250 (PrintLab navy), `UI_LINE`, `UI_INK` #F0F0F0, `UI_MUTED`, `UI_DIM`, accents `UI_CYAN` / `UI_GREEN` / `UI_YELLOW` / `UI_RED`, plus the 7 PrintLab filament colours (`ui_strip`).
- Fonts (`FT_LABEL` mono 10px tracked, `FT_MONO` 12, `FT_BODY` grotesk 15, `FT_HEAD` 24, `FT_NUM` 40 digits, `FT_HERO` 58 digits). Generated by `tools/fonts/gen_fonts.py`; NUM/HERO only contain `0-9,.:-+`.
- Draw text with `ui_text(s, x, baselineY, font, fg, bg, AL_L|AL_C|AL_R)`: y is the **baseline**. `ui_w`, `ui_fit` (ellipsis), `ui_wrap` for measuring/fitting.
- Spaces are swapped to U+00A0 inside `ui_text`/`ui_w` because TFT_eSPI guesses the width of 0x20; the fonts carry a real NBSP glyph.
- Layout: status bar 0–21 (hairline at 21), content 22–207, nav 208–239 (5 tabs × 64 px). Touch hit areas are constants in `ui.h` shared with `handleTap`.
- Voice/tone: headlines are short and end with a full stop ("Scan to pay.", "Today."); labels are uppercase mono with "01 / NAME" numbering.

## Verifying changes (no hardware here)
- `tools/check.sh` compiles the full sketch against stubs for core 2 and 3 with `-Wall -Wextra` and runs the audio unit test. Stubs live in `tools/check/stubs` and `tools/sim/stubs`; extend them when you use a new library API (and check the real library's signature first).
- `tools/preview.sh` renders every screen to `previews/` using a TFT_eSPI stand-in that parses the same VLW fonts and follows TFT_eSPI's datum/textWidth/alphaBlend rules. Look at the PNGs after any UI change. `--web` also screenshots the dashboard.
- QR codes in the simulator come from `tools/sim/stubs/qr_table.h`; add strings with `tools/sim/gen_qr.py` if a preview needs a new one.

## Direction
- Goal: deep integration with the maintainer's own business dashboard (PrintLab Nepal), built as a preset on top of a generic "Connect" layer so any management system can plug in: payments → system, orders → screen, status changes → system, system → speak. The device sits behind NAT, so cloud systems can't call it directly: inbound data has to be pulled by the device (polling/long-poll/SSE), outbound goes as webhooks.
